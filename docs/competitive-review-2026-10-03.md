# STRATA 竞品复核与产品发布门槛

检索日期：2026-10-03，Australia/Sydney（检索时 UTC 为 2026-10-02）。范围：读取根目录三份计划，实际打开下列官方页面；未登录、购买、运行竞品或联系客户。本文件是新增研究与建议，不修改既有计划，也不是当前代码完成情况审计。

建议继续验证 **ETABS→SAFE 交接与改版复核**。六项客户能力应共同服务这一流程。AI、确定性工具、ETABS 连接、规则引用、旧结果失效和私有部署已有公开产品实践，单独出现不能证明竞争优势。我们需要证明客户特定错误的检测覆盖、复核成本和交付可复用性。

## 2. 三个值得验证的差异假设

以下是建议的产品实验，不是已实现能力、专利新颖性或已证实优于竞品。

| 假设 | 要做的具体功能 | 公平基线及成功条件 | 何时放弃独立产品路线 |
|---|---|---|---|
| **H1：理解交接语义的检查包** | 为一个批准的软件版本组合建立交接清单：楼层、工况映射、单位/坐标/符号、自重与上部荷载范围、允许转换、独立参考和原始位置。区分批准变化、违规差异、未知；优先抓漏项、错映射与旧文件。 | 与客户最佳 CSI/Excel/脚本流程，以及能配置同任务的竞品比较。独立工程盲测中，关键错误通过 0 例；每类有效覆盖暂定 ≥80%；完整复核人时下降 ≥25%。 | 竞品配置或脚本通过同样门槛且全周期成本更低，则做连接器/实施服务。 |
| **H2：解释“为什么失效”的改版复核** | 输入、映射、规则、依据、人工意见建立依赖；变化后列出受影响检查与失效原因。未变部分仅在依赖可证时复用；依赖不明则全量重检。展示新增、消失、持续、待重检问题，保留历史意见。 | 先对比每次全量重检＋人工对账；固定 ≥30 个变更用例覆盖来源/规则/映射变更、删除、重命名、无关变化。所有受影响结论均失效；增量结果与全量技术结果逐项一致；再测节省复核人时。 | 只做普通文件 diff 或整体 stale 标记没有足够优势；若维护依赖的总成本高于节省成本，保留全量重检。 |
| **H3：可移交的复算与补证据包** | 每条发现导出机器可读输入、公式、容差、原始来源定位及版本；展示参考与模型值各自来源，不用同源复制冒充独立证据。NOT VERIFIED 自动形成具体补资料请求；新证据创建新运行。AI 仅帮助解释与找到资料。 | 与规则＋模板说明比较：独立复核者无需开发者协助可重放所有支持的确定性检查；每条结论来源定位完整；加入 AI 后完整复核人时再降 ≥10%，关键错误与无依据关键主张不增加。 | 只有更长文字、聊天或哈希不构成价值；达不到增量收益，保留模板、检索和证据包，关闭生成环节。 |

哈希证明保存内容一致，不能证明证据真实、来源独立或工程正确。证据独立性需要工程师确认采集路径及适用范围。

## 3. 对六项客户能力的发布门槛

这是待纳入主升级计划的验收建议。每项需记录负责人、基线版本、构建标识、测试集版本、实测结果和剩余阻塞。下列数量/阈值是拟定门槛，尚未达成；不能用测试条数替代业务准确率。

| 客户功能 | 发布时的可观察交付 | 建议的量化门槛 |
|---|---|---|
| F1 系统架构 | 项目、源文件、规则、运行、问题、审核独立实体；服务端共享与权限；模型不可用时规则仍运行 | 至少 2 个账号验证允许/拒绝/撤权路径；项目读写、下载、任务与检索越权用例 0 成功；重启后运行/意见可恢复；并发与重试不重复创建运行。正式上线另做备份恢复及回滚演练。 |
| F2 知识库/RAG | 授权文档原文定位；项目/版本/批准状态过滤；固定检查直接绑定批准规则，开放问答再检索 | 必检规则覆盖 100%；准备 ≥40 个独立标注问题，完整证据集 Recall@5 暂定 ≥90%，引用定位正确率 ≥95%；过期/越权引用 0；无答案题单列拒答结果。不能以检索失败把题移出分母。 |
| F3 工程推理流程 | 任务→规则→工程数据→确定性检查→证据核验→三态解释；每步可检查、可重放 | 强制用例（正常/错配/缺证据/未知单位/重复/边界/溢出）全部符合独立预期；0 无依据 PASS；充分资料范围内的每类覆盖 ≥80%，同时披露 NV/漏检/误报。真实客户试点仍需独立工程师真值。 |
| F4 工具调用 | 类型化白名单、固定调用预算、数据模式显式、权限与参数服务端控制；超时/取消/重试有轨迹 | 每个工具的成功、错误、超时与重复请求用例通过；拒绝未经授权工具/参数 100%；模型不能改写输入、容差或检查结论；每次运行调用数/耗时/失败理由可核对。精确预算由工作流注册表固定。 |
| F5 幻觉控制 | 生成内容只解释已保存结果；关键主张绑定来源；无法核证时降级或拒答；原文指令不改变流程 | ≥100 条固定对抗输入覆盖假条款、规则替换、越权、提示注入和伪造 PASS，0 关键越权/伪造依据/结果覆盖；逐条报告无依据关键主张和必需信息覆盖。没有实际模型评测时，只称控制逻辑测试通过。 |
| F6 测试与评估 | 规则单测、适配契约、端到端、故障恢复、检索/模型评测和客户保留集分开；发布前后同口径比较 | 全部阻断级用例通过；双运行时实现若并存，对共同支持契约 100% 结果一致；保留集按独立工程分组隔离；原始结果含每类分子/分母及实际输入，不以测试数量增长声称精度提高。 |

性能需先冻结机器、文件大小、对象数量、并发和冷/热缓存，再记录至少 30 次相同负载的 p50/p95、失败率及费用；目标从客户时限和实测基线确定。不能从一次合成样例计时承诺生产 SLA。

指标分母：有效覆盖＝正确 PASS/FAIL 实例÷运行前由工程师认定资料充分的范围内实例；错误通过＝错误 PASS÷真值 FAIL，并另报错误 PASS÷全部 PASS。检索 Recall@5 按每题前 5 个不同证据单元中命中的金标准单元数÷该题金标准单元数，再报告题均值与原始计数；多于 5 个必需单元的问题单列完整证据覆盖。引用定位正确不等于引用支持主张，两者分开评估。零分母记不可计算。

## 4. 前后对比与购买/自建决定

建议保留四条基线：A 客户最佳现有流程；B 当前冻结 demo；C 升级后的规则＋模板；D 在 C 上加检索/模型。竞品获准试用后加入 E。固定同一任务、允许资料和必填输出，任务顺序随机；运行者与工程真值标注者尽量分离。按工程分组报告，不把同建筑的多个版本视作独立工程。

每轮填写真实的 `before → after`：支持格式/版本数、批准规则数、充分资料覆盖、各类漏检/误报、NV 原因、来源定位、规则重放、受影响结果失效、完整人工复核时间、每份合格报告总成本。未测填“未测”，外部资源未到填“阻塞”，不得填 0 或推算提升。

沿用 `strategy_review.md` 的试点门槛：整体复核人时减少 ≥25%；新增 AI 相对 C 再减少 ≥10%；严重错误通过、越权或伪造依据任一出现即阻断试用。同时报告检查覆盖，避免全拒答获得“零错误”。时间改善用 `(基线人时−方案人时)/基线人时`，报告项目数及分布；小样本不外推生产错误率。

购买/自建按相同规则集、权限、保留期限、部署、支持和运行规模比较。总成本包括许可、配置/适配、基础设施、模型、复核/返工、支持及迁移；每项注明报价/实际/假设。先证明可复用适配与一个明确付费范围的试点，再考虑机构订阅。课程客户参与、满意反馈或意向均不等于收入。
