# 前端升级说明

这一轮从1.3.0 / `d0df3b0`继续开发，交付为1.4.0。重点是把已有能力整理成更容易独立使用的工作界面。计算方法、工程数值、批准规则、项目权限和人工确认条件沿用既有后端，没有通过改页面放宽判定。

当前导航按实际工作顺序排列：**Sources & revisions → Data adaptation → Rules & evidence → Check workspace → Findings & reports**。审计、成员权限和验证记录放在管理区。项目选择、语言切换和账户位置固定；切换项目不会展示上一项目的结果。报告仍从保存的运行记录导出，没有增加一个重复的报告页面。

## 改了什么

| 界面 | 具体处理 |
|---|---|
| 全站 | 浅色工作区、深蓝导航、青色主要操作；清晰的标题、帮助说明和间距；数量均来自当前项目记录；空项目有实际操作入口 |
| 资料与适配 | 上传、预览、保存区分；原字段/原值/单位/转换值/来源对照；预览保留原表单，可以直接继续创建快照；失败显示文件、表格或字段位置 |
| 规则 | 草稿/批准/退役状态有图标和文字；版本、参数、适用条件及原文引用可展开；无权限的批准操作禁用并解释 |
| 检查 | PASS/FAIL/NOT VERIFIED同时用文字、图标和颜色；小量发现默认展开；关键结论保持可见，计算值、容差、单位和来源完整保留 |
| 复核 | 保存记录、缺材料、修正及关联重检仍使用原流程；非reviewer不能提交人工复核；旧结果、原失败及更正理由保留 |
| 表格 | 本地筛选、稳定排序、分页、固定表头、局部滚动和完整值查看；数字排序不用浮点转换，显示精度不变 |
| 交互 | 同一表单防重复提交；提交前捕获数据，再冻结字段和相关按钮；保存中不关闭表单；未保存修改可继续编辑或明确放弃 |
| 双语 | EN/简体中文沿用统一语言文件；语言切换原位更新，不重建表单；原文、字段、数值、单位及用户输入不翻译 |

没有新增npm/Python依赖、数据库或前端框架。字体使用操作系统可用字体，SVG图标随源码提供；正常运行不请求字体CDN或图标服务。首次安装Python依赖和构建Docker基础镜像仍需要联网。

## 组件组织

| 文件 | 职责 |
|---|---|
| `web/design-system.css` | 颜色、字体、间距、圆角、阴影、尺寸、焦点和按钮/徽章/表单/面板基础样式 |
| `web/styles.css` | 导航、工作区、各页面、表格、弹窗及响应式布局 |
| `web/ui-foundation.js` | 本地SVG、展示层状态徽章、表格筛选/排序/分页/完整值查看和偏好恢复 |
| `web/dialog-controller.js` | 弹窗会话、初始/返回焦点、Escape/背景点击、未保存与保存中守卫 |
| `web/ui-page-state.js` | 按项目/页面/运行隔离的页内草稿、选择、展开状态、表格状态和焦点；不写入localStorage，不缓存密码或文件 |
| `web/app.js` | 沿用实际API和工作流，把上述组件接入八个现有页面；请求与选择的上下文守卫、权限展示和提交锁 |
| `web/editors.js` / `web/ocr-ui.js` | 既有编辑器和扫描页校对；迟到请求不能改另一弹窗；图未加载时不能确认识别数值 |
| `web/locales/en.js` / `zh-CN.js` | 新旧界面文案集中管理，内部状态值不变 |

后续新增页面文案先补两语言，展示状态使用`statusBadge`，表格用`enhanceTables`。涉及工程输入和规则的方法继续通过既有契约与确定性工具扩展，不能靠前端或提示词新增工程批准依据。

## 查看与使用

使用者解压发布包，在项目目录运行：

```sh
npm run setup
npm start
```

打开`http://127.0.0.1:4180`，首次创建自己的账号，无默认用户名或密码。按[安装说明](../../GETTING_STARTED.md)运行受控合成案例。Docker入口及实际验证见[Docker说明](DOCKER.md)。本机临时验收服务与个人4180、旧1.3.0的4193演示隔离，不将测试账号或数据库打入安装包。

改造前后截图见[截图对照](SCREENSHOTS.md)。验证范围、实际失败经过及未验证部分见[验收说明](VERIFICATION.md)；源码/镜像/安装包身份以发布包旁`release-verification-v1.4.json`为准。
